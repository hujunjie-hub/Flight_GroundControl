# Flight GroundControl 五大功能中心与九屏部署规范

- 版本：1.0
- 日期：2026-11-21
- 仓库：`hujunjie-hub/Flight_GroundControl`
- 视觉基线：用户确认的九屏独立页面设计，以及后续五大功能中心总览设计

## 1. 目标

把已确认的 Flight 地面站设计落到真实 QML 页面和现有 QGroundControl 功能链路中。设计图是布局、信息层级、卡片密度、导航组织和交互方式的目标，不是可直接贴入应用的静态背景图。

## 2. 五大功能中心

| 功能中心 | 页面入口 | 现有实现来源 |
|---|---|---|
| 总览总控 | 总览总控 | `FlightOverview.qml`；只读读取 Vehicle Facts、GPS、电池、Flight telemetry 和真实轨迹 |
| 飞行准备 | 传感器校准、遥控器配置、飞行模式、安全检查 | `FlightSensors.qml`、`FlightRadio.qml`、`FlightModesPage.qml`、`FlightSafety.qml` |
| 飞行监控 | 飞行健康、导航时序、遥控与链路、告警事件 | `FlightTelemetry.qml` 的四个数据页面，由五中心侧栏统一导航 |
| 设备与数据 | 云台设备、板载存储 | `FlightGimbal.qml`、`FlightStorage.qml` |
| 系统维护 | 参数中心、固件刷写 | `SetupParameterEditor.qml`、`FlightFirmwareInstall.qml` |

九屏原型中的飞控诊断屏包含总览、健康、导航时序和遥控链路信息。五中心拆分后，总览总控独立成为应用入口；飞行监控中的告警事件继续复用诊断页已有事件状态、严重度、来源、原因和接收时间信息，不复制或合成另一套事件数据。

## 3. 页面与数据约束

- 所有数值必须来自当前 active Vehicle、Fact、FactGroup、MAVLink 状态或现有控制器；不得将效果图中的示例数值写入生产代码。
- 缺失、无效、超时、通信中断和未上报必须保持各自语义，显示未知/等待/不可用；不得将其推断为健康。
- 总览页只展示状态和导航快捷入口，不新增 ARM、起飞、返航、降落或执行器命令通道。
- 传感器校准和遥控器校准继续由 Flight 固件/现有 VehicleComponent 驱动；必须保留上锁、连接、通道数量等既有门控。
- 飞行模式配置继续通过 Fact System 和现有参数映射工作；不得旁路参数下载和写入保护。
- 安全页只呈现飞控上报的 Ready-to-Fly、传感器、电池、链路等状态；返航和地理围栏能力不得在地面站端伪造。
- 飞控诊断保持只读；遥测不得授予 ARM、Permit、控制权或执行器提交权限。
- 云台姿态命令必须保留 Gimbal Manager 控制权、设备在线、姿态 freshness 和轴 capability 门控；不得强制抢占其他控制端。
- 板载存储保持只读。Flight 固件未实现 MAVLink Onboard Log 列表/读取/擦除时，必须明确说明暂不支持，不得显示虚构日志、容量或进度。
- 参数中心继续使用唯一机型绑定、参数 Fact、在线写入确认和回读闭环。
- 固件刷写继续使用现有 SWD programmer、目标探测、断连检查、写入和校验流程。

## 5. 导航行为

- Flight 页面采用五中心分组侧栏；每个子项直接打开现有功能页。
- 总览总控作为 Flight 配置视图默认入口。
- 飞行监控的四个子项由侧栏控制 `FlightTelemetry.qml` 当前页；该页面内部页签隐藏，避免与侧栏重复导航。
- 参数中心和固件刷写继续使用现有专用全页入口。
- 非 Flight 固件继续使用原 QGC VehicleConfigView 组件树，不改变其导航。

## 6. 开发阶段验收边界

本轮按用户要求在开发阶段集中完成页面移植，不运行 CI、Build、Unit、Integration 或 UI 自动化测试。所有未执行项目标记为 `NOT_RUN`；源码差异检查不等于构建或视觉验收通过。视觉验收须在集中验收阶段使用目标 Windows Release 程序完成 1672×941 与 100%/125%/150% DPI 截图比对。

## 7. 实施记录

### 2026-11-21 — 五中心导航与总览总控首批部署

- 将 Flight 配置侧栏重组为总览总控、飞行准备、飞行监控、设备与数据、系统维护五大功能中心。
- 新增 `FlightOverview.qml`：使用当前 Vehicle 的飞行模式、解锁/飞行状态、GPS、Battery、Ready-to-Fly、姿态、高度、速度、航程、事件计数和轨迹；无效或缺失数据保持未知。
- 总览快捷入口只导航到已有传感器、遥控器、诊断和任务规划页面，不新增飞行控制命令。
- 将 FlightTelemetry 页面选择交给五中心侧栏，隐藏重复的内部页签。
- 构建、测试和实际运行截图：`NOT_RUN`，待集中验收。


### 2026-11-21 — 其余页面视觉统一与数据说明

- 传感器校准页增加只读实时姿态参考，校准仍由 Flight 固件执行；没有新增地面站侧模拟传感器值。
- 遥控器、飞行模式、安全、云台、板载存储和固件刷写页面统一到深海青视觉令牌；安全/固件主要文案统一中文。
- 飞行模式参数绑定、上锁编辑门控、云台控制权和姿态新鲜度门控、存储只读边界、固件探测/断连/写入/校验流程保持不变。
- 组件路由改为按 QML source 文件定位，避免依赖翻译后的组件显示名称。
- 构建、测试、运行截图仍为 `NOT_RUN`；此记录仅表示源码移植已提交，不表示视觉验收通过。


- 顶栏状态信息按窗口宽度自适应隐藏次级字段；传感器姿态图标使用明确的图像坐标系旋转中心，避免缩放布局时旋转锚点漂移。
- 安全页电池电量仅接受 0–100% 有效值，并补充真实电压 Fact；无效值继续显示“未上报”。


- 总览地图不再通过持续绑定车辆坐标强制跟随，保留操作员平移/缩放；车辆轨迹通过 TrajectoryPoints 的新增、更新、清空信号实时维护，切换活动载具时重新装载对应轨迹。


- 总览总控现在不依赖完整参数下载即可打开；参数尚未就绪时，传感器/遥控器/诊断快捷入口禁用并提示等待参数下载，避免出现点击无响应的空操作。


- 总览、顶栏、传感器姿态参考和安全页在通信丢失时不继续把最后一帧遥测显示成实时值；地图保留最后位置并明确标记“通信中断”，其余实时数值显示“数据中断”或“—”。


- 总览页避免同屏重复：顶栏只保留载具身份、连接状态和时钟；GPS、电池、飞行模式、解锁/飞行状态集中在 KPI 区；健康卡片保留传感器健康、MAVLink 丢包率和事件数量，不重复显示 GPS/电池。


- MAVLink 丢包率只有在飞控已连接且收到有效消息后才显示数值；未开始接收消息时保持“未上报”，不把默认零值当作真实测量。


- 顶栏连接状态在 VehicleLinkManager 缺失时显示“未连接”；健康卡片颜色也遵循链路 freshness，避免通信中断时沿用最后一次绿色状态。


- 安全页不再沿用 SIL 示例动作作为通用飞控承诺；增加飞控实际暴露的 RTL/降落模式标识，并明确未接入的失效保护参数不显示为已配置。
