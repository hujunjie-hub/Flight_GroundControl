## 中期实施顺序

1. **稳定本地交付。** 在 PowerShell 7 中收敛为可重复执行的本地 Release 验收入口。增量构建、聚焦测试和全量验收复用同一配置。每轮使用独立日志与输出目录，保存失败时的 QtTest 细节、超时阶段和退出码。完成后由 GitHub Actions 复核推送的 `main` 提交。
2. **建立跨仓库契约验证。** 为发布端、ICD、GCS 方言与解释规则记录可追踪版本。把 UDP SIL 日志、消息覆盖和已知字段缺口纳入独立验收。所有页面状态保持只读诊断语义。
3. **统一遥测新鲜度并测量页面开销。** QML 目前有 1.0/5.5 秒显示阈值和 500 ms 可见页面刷新，C++ 另有 family stale 定时通知。传感器和链路行目前可能同时显示上次的“健康”和当前的“数据超时”。用单一阈值来源判断 family 和实例状态，实例过期时让主要状态显示超时，历史值可附时间展示。验收覆盖单实例停止、同 family 其他实例仍更新、恢复和车辆切换。先记录同一流量下的 QML delegate 重建次数、Fact 通知率、CPU 和界面刷新耗时，再评估是否需要拆分刷新路径。
4. **根据数据收敛维护成本。** 保存每轮 Unit/Integration 的耗时分布，优先处理反复失败或接近超时的测试。GeoTag、地图缓存和多车辆生命周期保留退出阶段诊断，性能或重构任务以可重复基线及可观察回归作为提交依据。
