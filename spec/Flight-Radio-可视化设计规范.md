## 1. 目标与范围

将右侧两个抽象圆形摇杆改为可辨识的双摇杆航模遥控器主体，并把当前接收的 RC 通道值实时叠加到两个云台位置。左侧校准操作区继续沿用现有布局和业务流程。

本次是展示层改造，不是遥控器协议、通道映射或飞控校准流程重构。

### 1.1 设计目标

1. 第一眼能识别为双摇杆航模发射机，而不是两个独立圆形仪表。
2. 遥控器主体具有机身、天线、肩部拨杆、微调件、显示屏、双云台、功能按键和结构细节。
3. 两个摇杆球的位置必须由当前 RC_CHANNELS 数据驱动，不能使用动画或静态假数据。
4. 保留日本手、美国手、中国手选择，并继续按当前模式映射通道。
5. 通道监视器继续展示全部已接收通道，增加清晰的 PWM 数值和无信号文本。
6. 校准、绑定、复制微调量继续走原有 `FlightRadioComponent` 和固件命令路径。

### 1.2 非目标

- 不仿制或暗示某一商业品牌/具体型号；新增图形为项目自有通用矢量插画。
- 不把插画中的装饰 LCD 内容当作实时遥测，不在 LCD 上伪造电压、RSSI、模式或飞行状态。
- 不修改 MAVLink 消息、RC_CHANNELS 解码、`FlightRcMonitor`、Vehicle 信号或通道有效性规则。
- 不改变校准命令、状态机、保存/取消、CRSF/ELRS 绑定或微调量复制逻辑。
- 不新增解锁、模式切换、飞行控制、执行器控制或任何遥控器写入操作。
- 不根据通道缺失推断接收机链路故障或飞控安全状态。

## 2. 页面信息架构

### 2.1 左侧：校准与配置

保留并稳定呈现：

- 横滚、俯仰、偏航、油门的实时 PWM 行程条。
- 开始校准、确认保存、取消和校准进度/提示。
- CRSF / ELRS 绑定。
- 复制微调量。
- 现有车辆状态、通道数和校准状态门控。

本轮只补充稳定的 `objectName` 供 UI 集成测试定位，不改变按钮启用条件和回调。

### 2.2 右侧：发射机可视化

从上至下：

1. 遥控器实时状态标题与通道数据接收提示。
2. 日本手 / 美国手 / 中国手模式选择。
3. 完整遥控器主体插画及左右云台实时摇杆位置。
4. 左/右摇杆当前使用的通道编号。
5. 两列通道监视器：通道号、PWM 行程条、PWM 数值。

状态提示只表述地面站是否收到通道数据，例如“等待通道数据”“已收到 8 路通道”。不得把“已收到通道”扩展成“链路健康”“接收机正常”或“飞行安全”。

## 3. 遥控器插画规范

### 3.1 资源

- 文件：`resources/FlightTransmitter.svg`
- 资源别名：`qrc:/res/FlightTransmitter.svg`
- 画布：900 × 640，透明背景。
- 视觉：深石墨机身、金属边缘、暗色 LCD、实体开关/旋钮和双云台结构；与现有深色工业界面一致。
- 插画应按宽度等比缩放，主体最大显示宽度 520 px，不拉伸、不裁切。

### 3.2 云台定位坐标

插画 viewBox 固定为 900 × 640，QML 实时叠加坐标按以下中心定位：

| 云台 | SVG 中心 | 归一化 X | 归一化 Y |
|---|---:|---:|---:|
| 左云台 | (280, 405) | 280 / 900 | 405 / 640 |
| 右云台 | (620, 405) | 620 / 900 | 405 / 640 |

云台插画的外圈和结构细节属于静态外观；摇杆杆身和黄色摇杆球由 QML 叠加层实时绘制。只有横向、纵向两个通道值都可用时，才显示实时摇杆球和杆身。数据缺失时保留云台外观，但隐藏实时标记。

## 4. 摇杆模式和实时数据

沿用 `FlightRadio.qml` 当前 `stickChannels` 映射，数组元素均为从 0 开始的 RC 通道索引：

| 模式 | 左摇杆 (横向/纵向) | 右摇杆 (横向/纵向) |
|---|---|---|
| 日本手 | CH4 / CH2 | CH1 / CH3 |
| 美国手 | CH4 / CH3 | CH1 / CH2 |
| 中国手 | CH1 / CH2 | CH4 / CH3 |

映射必须与源码中的模式设置一致，不得因插画左右位置调整而交换通道。

PWM 位置继续使用当前范围映射：

`fraction = clamp((PWM - 1000) / 1000, 0, 1)`

- 横向：fraction 0 对应最左，1 对应最右。
- 纵向：fraction 0 对应最下，1 对应最上。
- 中位约为 1500 µs。
- 通道值缺失时显示“无信号”，不显示伪造的 1500。
- 该位置只用于显示接收的 RC 输入，不构成控制输出，也不反馈修改遥控器参数。

## 5. 通道监视器

- 保留 `FlightRcMonitor.channelCount` 和 `channels` 原始数据来源。
- 按当前收到的通道数量生成通道行；两列排列。
- 每行显示 CH 编号、PWM 位置条、PWM 数值（µs）。
- 缺失通道明确显示“无信号”，位置条不显示有效位置点。
- 不自行增加通道、补齐虚构值或推断链路质量。
- 通道状态提示只表达“是否收到通道数据”和数量。

## 6. 校准与安全边界

以下业务逻辑保持不变：

- `_canCalibrate` 仍要求 Vehicle 存在、未解锁、未飞行且链路未报告 communicationLost。
- 开始校准仍要求至少 4 路通道且校准状态不为进行中。
- 保存和取消仍只在校准进行中启用。
- 复制微调量仍要求校准完成和至少 4 路通道。
- CRSF / ELRS 绑定仍受车辆状态和校准状态门控。
- 所有动作仍调用原 `FlightRadioComponent` 方法，不新增 QML 直发 MAVLink 路径。

插画不代表真实遥控器已连接；通道数大于零只表示当前收到过 RC_CHANNELS 数据，不构成链路健康或飞行放行结论。

## 7. 响应式与视觉规范

- 页面可用宽度 ≥ 1080 px：校准区与发射机区两列布局。
- 页面可用宽度 < 1080 px：上下单列布局，避免右侧插画和通道监视器被压缩裁切。
- 发射机插画显示宽度不超过 520 px，保持 900:640 比例。
- 右侧面板最小宽度 320 px；窄屏时允许纵向滚动。
- 保留现有深色背景和青绿色强调；实时摇杆球使用淡黄色，只有真实有效数据时显示。
- 不增加闪烁、自动摆动、循环动画或虚构数据曲线。

## 8. UI 集成测试与验收

新增 `FlightRadioPageUITest`，通过真实 MockLink → MAVLink → Vehicle → FlightRcMonitor → QML 路径验证：

1. 遥控器页面可打开，插画资源可见且有有效尺寸。
2. 左右云台叠加层均存在；没有 RC_CHANNELS 时实时标记不可用。
3. 注入 8 路 RC_CHANNELS，未使用通道使用 `UINT16_MAX`，确保 Vehicle 按连续通道规则解码。
4. 美国手默认映射下，左摇杆使用 CH4/CH3，右摇杆使用 CH1/CH2；注入值正确反映到归一化位置。
5. 通道监视器显示通道数量和 PWM 值。
6. 开始校准、保存、取消、绑定、复制微调量控件仍存在；保存/取消未处于校准状态时保持禁用。
7. 不触发任何校准、绑定或飞行控制命令。

测试标签为 Integration / NoSanitizer。完整 Windows x64 MSVC Release、Unit、Integration、可执行文件、Installer、Clean Install 和 Installed Runtime 门禁仍按项目总规范执行。当前会话不能代替用户本地 Windows 产品构建，未执行项必须记录为 NOT_RUN。
